# Task: Semantic Identity and Relationship Repair

## Problem Statement
Plans L–R established format-aware text dispatch, typed semantic observations, multi-entity resolution, evidence-backed provider promotion, rich append-only reconciliation, replay-built multi-edge reads, the Lantern Keeper fixture, and public structured/search surfaces. The remaining semantic defects are concentrated in four connected seams: accepted canonical entities are not durable first-class ledger identities; opaque refs are not accompanied by queryable display labels and aliases; canonical refs are still derived from a source-bound cluster; and valid relationship predicates such as the Lantern Keeper sibling relation are discarded.

This plan repairs those defects through the existing append-only semantic ledger, reducer/replay projections, `SourceMembershipService`, bounded query/search services, and the real nine-stage `StageWork` registry. It must preserve Plan N’s ledger-first string-reference representation (`entity_mention.entity_id` remains NULL for non-UUID refs), Plan R’s committed-evidence provider hydration, exact OCFL/evidence provenance, deterministic IDs, human override/lock precedence, reversible merge/split, descendant-only invalidation, idempotent retries/reruns, and projection freshness gates. The SQL `entity` table remains a legacy/typed relational record and is never promoted to semantic authority.

**Prerequisite:** Completed Plan R and the preserved L–P foundations, with Q’s verification and the existing semantic capability reports retained as historical evidence. This is one follow-up plan after R; it does not create a DD, research/adversarial artifact, or second release gate.

**Scope:** `src/umd/domain/ids.py`, `src/umd/domain/events.py`, `src/umd/domain/models.py`, `schemas/events/EntityResolved/`, `src/umd/resolution/service.py`, `src/umd/resolution/mentions.py`, `src/umd/resolution/resolution.py`, `src/umd/reconciliation/reconciler.py`, `src/umd/jobs/production.py`, `src/umd/storage/postgres/reducer.py`, `src/umd/storage/postgres/ledger.py`, `src/umd/storage/postgres/repositories.py`, `src/umd/projections/current.py`, `src/umd/projections/query.py`, `src/umd/projections/search.py`, `src/umd/projections/edges.py`, `src/umd/projections/tables.py` only when an existing disposable projection shape requires it, `src/umd/api/schemas.py`, `src/umd/api/routers/entities.py`, `src/umd/api/routers/query.py`, `src/umd/api/routers/search.py`, `tests/fixtures.py`, focused resolution/reconciliation/ledger/replay/query/search tests, `tests/test_production_stage_registry.py`, and public API E2E tests. Do not alter Hatchet, the stage DAG, OCFL storage, deployment architecture, or modality/provider gates.
