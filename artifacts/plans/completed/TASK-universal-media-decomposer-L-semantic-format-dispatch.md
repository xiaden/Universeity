# Task: Semantic Capability L — Production Text and Book Format Dispatch

## Problem Statement
The first implementation of Plan L added the shared format-aware dispatch seam and routed `FORMAT_ANALYSIS`, `BASIC_SEGMENTATION`, and `LOW_LEVEL_EXTRACTION`, but QA Round 1 found concrete gaps before the plan can be accepted. `STRUCTURAL_ANALYSIS` still reconstructs text with `_parsed_text`/`normalize_txt` from raw OCFL bytes, low-level paragraph evidence still pairs retry-interleaved segment rows positionally, in-process EPUB extraction has no decompression ceiling, the text-depth contract overstates Markdown/EPUB delivery, and production documentation is stale. This amendment repairs only those gaps while preserving the nine-stage DAG, `STAGE_ORDER`, Hatchet/job topology, OCFL authority, typed PostgreSQL evidence/segments, append-only semantic ledger authority, idempotency/retry/invalidation behavior, and the generic non-audiobook domain.

**Prerequisite:** Existing Plans A–K foundations and the completed portions of Plan L are the baseline. Later semantic-capability plans depend on Plan L's parsed-document and segment provenance contract. Do not create another DD/research artifact or redesign the architecture.

**Scope:** `src/umd/jobs/production.py`, `src/umd/extractors/{dispatch,epub}.py`, `tests/test_production_stage_registry.py`, focused production/parser/segmentation tests, `CONTRACTS.md`, the existing DD depth wording, and the root validation-count documentation. Preserve the repository's stdlib ZIP/XML EPUB parser and pure Markdown parser; do not reintroduce `ebooklib`, pandoc, a second dispatch framework, or a binary-to-text fallback.
