# Task: Semantic Identity and Relationship Boundary Correctness

## Problem Statement

**Prerequisite:** Completed Plan T (`TASK-universal-media-decomposer-T-semantic-identity-boundary-hardening.md`) at the e74cb21-era baseline. Plan T and its hosted-green report are historical context and must not be amended or architecturally reopened.

After Plan T, the semantic identity and relationship implementation has several correctness gaps at the production and public boundaries. `ResolutionInputBuilder` already accepts committed assignments, explicit correspondence, and human support, but the real `ENTITY_RESOLUTION` stage supplies only committed assignments; `CROSS_SOURCE_ALIGNMENT` records alignment afterward without a durable resolution-generation handoff. Typed `RELATED_TO` facts carry `relationship_type` as data but omit it from fact identity, so distinct relationship types can collide and correction/invalidation can affect the wrong edge. The generic typed fallback still has a hardcoded recognized set. Identity classification is not a certainty ceiling for dependent assertions, canonical read provenance is incomplete, public UUID forms are inconsistent, entity creation accepts a spoofable body actor, and membership arrays/search scope lose source/work correlation through Cartesian expansion.

This plan repairs those seams within the existing architecture. It preserves one `ENTITY_RESOLUTION` authority, read-only committed-resolution consumption by `SEMANTIC_RECONCILIATION`, the append-only PostgreSQL ledger and pure reducer/replay, OCFL/source authority, Plan N Option B ledger-first string refs with nullable UUID FKs, replay-only projection writers, the immutable predicate registry, the fixed nine-stage DAG, the existing Hatchet scheduler/topology, bounded invalidation, and existing authentication/roles. It introduces no identity store, graph database, second scheduler, fabricated entity rows, silent fallback joins, weakened tests, or hermetic substitute for hosted acceptance.

**Amendment (PLANNING_GAP):** The terminal `CURRENT_SEARCH_PROJECTION` stage currently replays only `CurrentTierOneBuilder`, so production never advances the registered `semantic_edges` or `search` projections. The existing `SearchProjectionBuilder` freshness guard and `ConsistencyGuard` semantics are correct but unexercised at the public boundary while those checkpoints remain at zero. This amendment wires the existing replay-only builders into that same ninth stage in the fixed order current tier → active semantic edges → search, then reopens the public edge/search observations and adds focused order, checkpoint, wipe/replay, and lag-guard verification. No new stage, scheduler, endpoint, store, authority, or migration is planned.

The authoritative request is the nine-item requirement ledger supplied with this plan task. Precedence is: authoritative user request > applicable existing design/contracts > this plan > current code/tests. Every requirement is mapped below; an implementation that omits, weakens, defers, inverts, or contradicts one is `REQUIREMENT_DRIFT` and must stop rather than silently narrowing scope.
