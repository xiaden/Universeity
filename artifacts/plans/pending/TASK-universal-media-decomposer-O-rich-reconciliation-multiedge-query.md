# Task: Semantic Capability O — Rich Ledger Reconciliation and Active Multi-Edge Reads

## Problem Statement
`SEMANTIC_RECONCILIATION` currently appends only one `RECONCILED_SOURCE` assertion. The typed predicate/entity/evidence tables and bounded query/search surfaces are present but starved, while `current_state` intentionally keeps one winning value per `(entity_ref, predicate)`. This plan emits a rich, evidence-backed semantic graph through the append-only ledger and adds a replay-built/read-side active multi-edge representation without changing the single-valued current property, introducing relation entities, or making projections authoritative.

**Prerequisite:** `TASK-universal-media-decomposer-N-multi-entity-resolution.md`. It consumes typed semantic observations and resolved/unresolved mention mappings. It also depends on L's segment IDs and M's provenance contract.

**Scope:** `src/umd/jobs/production.py`, `src/umd/application/commands.py`, `src/umd/domain/{models,events}.py`, `src/umd/storage/postgres/{ledger,reducer,tables,repositories}.py`, `migrations/versions/0008_semantic_edge_projection.py` (or the next head migration), `src/umd/projections/{base,current,query,search,question,tables}.py`, focused projection/query/replay tests, and the Plan O search/data-model documentation surfaces (`docs/query-search.md`, `docs/data-model.md`, `README.md`). Do not redesign Hatchet/jobs, OCFL, the append-only ledger, `current_state` winner semantics, or introduce Neo4j/RDF/separate DB.
