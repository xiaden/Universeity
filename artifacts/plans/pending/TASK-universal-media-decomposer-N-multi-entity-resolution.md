# Task: Semantic Capability N — Multi-Entity Resolution and Alias Decisions

## Problem Statement
The production `ENTITY_RESOLUTION` binding currently creates one synthetic `entity:canonical:{source_id}` value and aliases all candidate mentions to it. Existing `SourceMention`, `MentionService`, `MentionBlockIndex`, linkage helpers, reversible `Resolver.merge/alias/split`, quarantine, and lock/override commands are present but not composed into production text work. This plan replaces the single-canonical placeholder with deterministic multi-entity resolution while preserving mention history, reversible operations, human authority, and unresolved ambiguity. The completed P1–P3 work exposed a live persistence gap: service canonical refs are strings, while `entity_mention.entity_id` and `current_entity_map` are UUID-constrained. Phase 4 closes that gap without introducing entity-table materialization or changing the DAG.

**Prerequisite:** `TASK-universal-media-decomposer-M-semantic-provider-contract.md` and L's segment/evidence identity. Resolution consumes typed mentions/aliases and does not infer from raw bytes or write projections directly.

**Scope:** `src/umd/resolution/{mentions,candidates,linkage,resolution,dispatch}.py`, `src/umd/jobs/production.py`, relevant `src/umd/domain/{models,events}.py`, `src/umd/application/commands.py`, `src/umd/storage/postgres/{tables,reducer}.py`, `src/umd/projections/{query,search}.py`, entity/mention repositories and existing migrations only if a typed field is truly required, plus resolution/StageWork/replay tests. Do not replace the append-only ledger, delete mentions, create relation entities, or add a separate entity database.

## Amendment requirement ledger (authoritative and unchanged)
- Replace the placeholder production `ENTITY_RESOLUTION` with real multi-entity resolution: candidate mentions including names, aliases, titles/common descriptions resolve to zero/one/many canonical entities using normalized form, segment context, co-occurrence, type, existing canonical entities, optional model assistance, confidence, contradictions, human-confirmed aliases/locks/overrides.
- Preserve uncertain aliases as ambiguous/reviewable; never destructively collapse source/evidence/semantics; reruns are idempotent; human confirmations outrank machine reruns; ledger authority, reversible merge/split, provenance, confidence, and uncertainty remain intact.
- Add coverage for at least three distinct characters with aliases proving no collapse and an ambiguous alias remaining unresolved. Keep the implementation generic/non-audiobook, make no topology redesign, and add no new DD/research artifact.
- Preserve the append-only ledger, evidence provenance, confidence/uncertainty, and existing architecture. Task.md §10 KG coverage remains applicable to entities, characters, aliases, scenes, utterances, presence, speaker identity, states, emotions, relationships, contradictions, and the other listed semantic categories without fabricating or deleting source claims.
