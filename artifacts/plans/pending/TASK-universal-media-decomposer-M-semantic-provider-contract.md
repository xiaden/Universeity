# Task: Semantic Capability M — Typed Optional Text Analysis

## Problem Statement
`src/umd/analysis/text_structural.py::analyze_text` is a deterministic paragraph-level baseline with chapter-1 locators and candidate evidence only. The existing `ModelProvider` contract is typed at the call envelope but permits arbitrary provider output, and no production text stage validates provider semantic results before promotion. This plan adds an optional provider-backed semantic analysis path inside the existing DAG stage(s), retaining deterministic/reference analysis as the safe baseline and making provider absence, malformed output, unsupported providers, and weak evidence honest rather than silently authoritative.

**Prerequisite:** `TASK-universal-media-decomposer-L-semantic-format-dispatch.md`. The analyzer consumes L's format-aware, segment-linked document and must not reconstruct text from OCFL bytes.

**Scope:** `src/umd/analysis/text_structural.py`, new or adjacent typed semantic-analysis module under `src/umd/analysis/`, `src/umd/models/provider.py`, `src/umd/models/registry.py` and existing adapters/capability reporting, `src/umd/jobs/production.py`, domain evidence/event helpers, provider/analysis tests, and provider documentation. Do not add a DAG stage, replace the provider abstraction, let a model write semantic state, or introduce audiobook/TTS/Alexandria-specific schemas.

## Completion Criteria
- Deterministic and provider-backed text analysis return one validated, generic typed result contract covering every requested semantic observation category where evidence supports it.
- Every promoted candidate carries exact segment evidence, confidence, provider/model/config/prompt/version provenance where applicable, and no provider can write semantic or projection state directly.
- Malformed, unsupported, gated, or unavailable providers degrade to the deterministic/reference baseline with explicit status/warnings; strict Ruff/mypy and focused provider/analysis tests pass.
